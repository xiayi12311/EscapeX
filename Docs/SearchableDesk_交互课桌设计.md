- 日期：2026-10-23

- 项目：EscapeX（https://github.com/xiayi12311/EscapeX）
- 本文保存在工作区项目资料目录；尚未同步到编辑器工程仓库。
- 知识库依据：2026-10-22 官方文档快照；编辑器版本待实施时确认。

## 1. 玩法规则

玩家贴近关闭的课桌时显示“搜索”。点击后开始搜索读秒；读秒期间玩家可以移动，但超出允许距离即中断，进度清零。再次靠近并点击需要重新读秒。

读秒成功后，课桌播放抽屉拉开的 Sequence，露出内容物并触发对应演出，包括屏幕 UI 特效、系统广播、语音等。服务器负责成功判定、内容结果及总次数；客户端负责显示和演出。

默认每张课桌每次重置后只允许成功搜索一次，打开后保持打开。同桌同时只允许一名玩家搜索，同一玩家同时只允许搜索一张课桌。其他玩家可看到课桌被占用的提示。

“总搜索次数”指本局所有课桌成功打开的累计次数，中断、失败和重复请求不计入。重置后再次成功打开同一张课桌，会再次计数。

### 固定次数内容

| 成功后的总次数 | 最终内容 | 演出 |
| --- | --- | --- |
| 5 | 固定纸条（NoteEvent_05） | 揭示纸条并播报对应系统广播 |
| 10 | 固定纸条（NoteEvent_10） | 揭示纸条并播报对应系统广播 |
| 其他 | 课桌预先抽取的随机内容 | 该随机结果配置的演出 |

第 5、10 次规则可配置。固定纸条覆盖当前课桌的随机结果，不叠加原随机效果；纸条内容及广播可以分别配置。没有独立的“达到阈值额外广播”分支，广播属于固定纸条结果。

| --- | --- | --- |

以上名称为项目自定义设计，不代表已存在的文件或编辑器原生 API。通过事件和结果配置连接玩法与表现，不在课桌脚本中堆积具体特效分支。

## 3. 状态机

```text
Closed --有效搜索请求--> Searching --时间到且最终校验通过--> Opening --> Opened
                           |
                           +--超距/死亡/断线--> Closed（进度清零）

任意状态 --ResetDesk--> Closed（立即恢复、重新随机）
```

- Closed：关闭，可开始搜索。
- Searching：被一名玩家占用，服务器推进读秒。
- Opening：搜索成功已提交，客户端播放打开动画。此时离开不撤销成功或计数。
- Opened：动画结束，保持打开，不能再次搜索。
- 状态推进依据服务器时间，不依赖客户端动画完成通知。

## 4. 搜索流程与距离判定

1. 范围检测控制“搜索”按钮显示。按钮可见性仅为交互提示，不能代替服务器校验。
2. 请求到达服务器后检查：课桌及玩家有效、玩家存活、课桌关闭且未占用、玩家未搜索其他桌、距离有效。
3. 通过后建立搜索会话，记录玩家、交互编号和服务器开始/结束时间。
4. 仅对活跃搜索进行周期检查，建议初始间隔 0.1 秒，可用离开范围事件辅助取消。
5. 超距、死亡、断线、课桌销毁时取消，清除计时器和双向占用关系，通知客户端关闭进度。
6. 时间到再次校验版本、玩家、状态及距离；通过后交由管理器提交成功。

距离以固定交互挂点为基准。InteractRadius 控制开始搜索，CancelRadius 控制中断，后者建议略大以避免边缘抖动。具体数值与读秒时长待场景体验确定。

客户端根据服务器时间基准平滑绘制进度，不逐帧同步百分比。进度到零仍须等待成功确认，不能自行开桌。

## 5. 内容随机与成功提交

课桌初始化及每次重置时，由服务器按权重池抽取并保存候选内容。中断搜索不重新随机；重新随机允许抽到相同内容。成功前不向客户端公开候选结果。

成功提交在服务器连续执行，中间不插入异步等待：

1. 检查搜索会话仍有效、本次成功事件未提交。
2. 计算 NextCount = TotalOpenedCount + 1。
3. 若 NextCount 命中固定次数配置，最终结果取对应纸条；否则取预抽内容。
4. 锁定最终结果及 Opening 状态，登记成功事件，释放搜索占用。
5. 更新总次数，发布课桌状态及演出事件。

多人同时完成时，以服务器实际提交顺序确定第 5、10 次，只能各有一张课桌命中。需防范回调重入和重复消息，不通过客户端上报完成来增加计数。

## 6. 表现与同步

- Sequence 绑定当前课桌实例，使用抽屉相对变换，避免多桌共用资源时移动到其他桌的位置。
- 内容物先准备好，在 RevealOffset 指定的揭示时刻显示并触发结果演出。
- 每个结果可配置多个效果：类型、资源、延迟、时长、受众、优先级。
- 抽屉与内容物对所有观察者一致；UI 特效可仅针对搜索玩家，世界声音可面向附近玩家，系统广播面向全体玩家。
- 服务器确定揭示时间并下发事件标识；全局广播不能由每个观察客户端的动画回调重复发起。
- Opening 同步包含开始时间；迟到的客户端按时间恢复动画进度，已过揭示时间则直接恢复物件显示。
- 迟加入或重新进入同步范围时恢复当前抽屉和内容物，不补播历史惊吓、语音或广播。
- 本地动画/资源失败不撤销服务器成功及总计数。演出结束保持抽屉最终姿态。

## 7. 数据设计

| 范围 | 关键字段 |
| --- | --- |
| 课桌配置 | DeskId、SearchDuration、InteractRadius、CancelRadius、OutcomePoolId、OpenSequence、RevealOffset、OpenDuration |
| 单桌运行状态 | State、ResetVersion、InteractionId、SearchingPlayerId、SearchStartTime、SearchEndTime、CandidateOutcomeId、FinalOutcomeId、OpenEventId、OpenStartTime |
| 管理器 | 课桌注册表、玩家占用表、活跃搜索表、TotalOpenedCount、CounterEpoch、已提交事件去重记录 |
| 结果配置 | OutcomeId、内容物资源、效果列表及受众 |
| 固定次数配置 | 5 → NoteEvent_05，10 → NoteEvent_10 |

CandidateOutcomeId 仅服务器保存。向客户端复制最终显示所需的数据；权威玩法数据不能由客户端改写。

## 8. 对外接口（服务器）

以下为拟定的项目公共接口，供特殊事件及其他玩法模块调用，不直接开放给客户端：

| 接口 | 行为 |
| --- | --- |
| GetOpenedCount() | 返回当前总成功搜索次数 |
| ResetOpenedCount() | 总次数归零并开启新的计数周期，不改变课桌或取消搜索 |
| ResetDesk(DeskActor) | 强制重置指定课桌，不改变总次数 |
| ResetAllDesks() | 强制重置所有已注册有效课桌，不改变总次数 |

ResetDesk 对无效或未注册 Actor 返回失败及原因；对已关闭课桌调用仍执行重新随机和版本更新。具体返回结构在编码时统一。

### 8.1 计数归零

ResetOpenedCount 将 TotalOpenedCount 设为 0，CounterEpoch 加一。新周期第 5、10 次再次触发固定纸条。已打开课桌保持原样，正在搜索的会话继续，随后成功计入新周期。

清零不能删除仍用于防止旧事件重放的去重依据。已发送/播放的广播不撤回。事件使用计数周期及成功事件编号去重。

### 8.2 单桌强制重置

无论当前状态如何，立即执行：

1. ResetVersion 加一，使旧请求、计时器及延迟效果失效。
2. 取消搜索及打开阶段计时器，释放玩家与课桌占用。
3. 清除搜索玩家与时间，立即关闭对应进度 UI。
4. 停止 Sequence 并直接恢复初始抽屉变换，不播放关闭过渡。
5. 移除旧内容物，停止该课桌仍可取消的专属效果。
6. 清除旧最终结果，服务器重新抽取候选内容。
7. 状态置 Closed，同步新版本；客户端收到后立即恢复初始表现。

“立即”指服务器调用时即时生效，客户端收到同步后即时应用，仍受正常网络延迟影响。

课桌重置不自动撤销已经发出的全局广播或已执行的其他系统事件。

### 8.3 全部重置

管理器维护 DeskId → DeskActor 注册表。课桌生成注册、销毁注销；全部重置遍历当前有效实例并复用单桌重置逻辑。之后新生成的课桌初始化为关闭并随机候选内容。

特殊事件需要全部恢复并重新累计时，在同一段服务器逻辑中依次调用 ResetAllDesks()、ResetOpenedCount()，中间不异步等待。

## 9. 版本与竞态约束

搜索、成功事件、表现消息和回调均关联 DeskId、ResetVersion、InteractionId；成功另有唯一 OpenEventId。任何回调执行前检查版本，客户端忽略旧版本消息。

- 先重置后到达旧完成回调：回调失效，不开桌、不计数、不演出。
- 先成功提交后重置：成功已计数，随后恢复关闭，不扣减次数。
- 旧取消请求不能取消新搜索，旧演出结束不能把重置后的桌子改成 Opened。
- 重置后新成功产生新的事件编号，可再次计数。
- 客户端请求需绑定其实际玩家身份；客户端时间、玩家标识和距离声明不能作为成功依据。

## 10. 验收条件

| 场景 | 预期 |
| --- | --- |
| 靠近关闭课桌并点击 | 出现“搜索”，开始读秒 |
| 读秒中超距后返回 | 即时取消，重新点击从零开始 |
| 完成前最后一刻超距 | 最终校验失败，不开桌、不计数 |
| 两人同时搜索同桌 | 仅一人获得占用，最多成功一次 |
| 重复点击或旧完成回调 | 不重复计时、抽奖或计数 |
| 普通次数完成 | 显示预抽物件及其配置演出 |
| 第 5、10 次完成 | 当前课桌显示对应纸条，广播一次，无原随机效果 |
| 多桌同时完成跨过 5 或 10 | 按服务器提交顺序唯一命中 |
| 读秒中重置单桌/全部桌 | 读秒消失、占用释放、状态关闭、候选重新随机 |
| 动画中或打开后重置 | Sequence 停止，抽屉立即关闭、旧物件移除 |
| 重置后收到旧动画/搜索回调 | 不改变新状态，不增加次数 |
| 只重置课桌 | 次数不变，重搜成功后继续累计 |
| 只清零次数 | 桌子不变，进行中搜索继续，新周期重新命中 5、10 |
| 玩家死亡/断线或桌子销毁 | 及时取消搜索并清理引用 |
| 迟加入及恢复同步 | 抽屉和内容正确，不补播历史一次性效果 |
| 多张桌使用同一 Sequence 资源 | 各自播放自己的抽屉动画 |

### 玩家被抓住后的课桌轮次重置（2026-10-26补充）

任意玩家在服务器成功进入抓取会话、控制锁生效后，立即对全体玩家执行ResetAllDesks和ResetOpenedCount。所有未完成搜索立刻取消、已打开课桌立刻关闭、内容候选重新随机，成功搜索总数归零，第5/10次固定纸条规则重新计数。抓捕失败和重复请求不触发；押送、绑柱、释放阶段不重复重置。
